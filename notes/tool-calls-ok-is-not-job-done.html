Note · Agent evaluation

Tool calls OK is not the job done

An agent can use every tool correctly and still fail the person who asked. Check the outcome first.

Most agent evaluation starts with the trace: did it call the right tools, with valid arguments, in a sensible order? That's necessary, and it isn't enough.

Take a journey-planning demo. Someone asks for a train late in the evening. The agent searches, picks a connection and books it. Every tool call is valid. The booking is several hours after the time they asked for. By the trace, a success. For the person, a failure.

Check the result against the request

So in my evaluation work I add a check on the final outcome, next to the checks on tool use and grounding. For the train, the verifier compares the booked time with the requested time. The question is always the same: did the thing the person wanted actually happen?

Then find where it broke

  • Deterministic checks wherever the answer can be computed: times, totals, IDs, formats.
  • Evaluation datasets with the requests that matter, including the awkward ones.
  • Trace reviews to see which step went wrong.
  • Quality gates that name the failing behaviour. “Booked the wrong departure time” tells you what to fix. “Eval failed” doesn't.

A healthy service, a valid tool call and a correct outcome are three different claims. Test all three.
