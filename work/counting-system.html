From a flash photo to a count

Counting small watch components from photos taken under flash, and the backend, security and cloud setup that make it usable.

Problem
A watchmaking manufacturer needed to count different small components photographed under flash illumination.
My role
The counting algorithm, the application backend, the security layer, the deployment architecture and the CI/CD pipelines.
Approach
One owner for the whole path, from image to API, on GCP behind an API management layer.
Outcome
Faster, more accurate counting, as reported by the users. The architecture is designed to grow from a few machines to thousands; that is a design target, not a measured fleet.

How it fits together

  1. Flash capture
  2. Counting algorithm
  3. Application backend
  4. Security layer and API management
  5. GCP
  6. CI/CD for every release

What I did

  • Wrote the counting algorithm for different component types.
  • Built the backend that serves it and the security layer in front of it.
  • Designed the deployment architecture on GCP, with API management as the entry point.
  • Set up CI/CD so releases are repeatable.

Decisions worth explaining

  • Algorithm and infrastructure owned by the same person. Changes to the model and to the way it is served don't wait on a handover.
  • Built for more machines from the start. The GCP and API management design targets growth from a few machines to thousands, so adding stations is not a redesign.

Lesson

The algorithm is half the delivery. Users notice whether the count arrives fast, every time.
