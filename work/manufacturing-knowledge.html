Case study · Manufacturing · Agent Ops

Manufacturing knowledge an assistant can cite

Configuration exports, process documents and operating records, turned into answers that point back to their source and admit what is missing.

Problem
Manufacturing knowledge is spread across many artifacts. An assistant has to connect them while keeping every answer traceable.
My role
Deployment and release workflows, with related testing and documentation. The broader application was built by a team.
Approach
A staged pipeline that keeps intermediate artifacts, retrieval scoped to one run, and gaps shown as gaps.
Outcome
Repeatable releases for a staged knowledge pipeline. No adoption, accuracy or time-saving figures are claimed.

How it fits together

  1. Engineering inputs
  2. Input validation
  3. Staged extraction
  4. Artifacts with source references
  5. Run-scoped retrieval
  6. Assistant
  7. Answer with evidence and gaps

Conceptual view. Service names, network boundaries and deployment configuration are left out.

What I did

  • Built the deployment and release workflows, so every running version maps to a known change.
  • Contributed tests and documentation around the staged pipeline.

Decisions worth explaining

  • Keep intermediate artifacts, so a failure can be investigated at the stage that caused it.
  • Scope retrieval to the selected run, to avoid mixing unrelated inputs.
  • Label facts, inferences and gaps differently.
  • Tie deployment artifacts to a controlled release, so changes can be identified.

Lesson

The boring parts (keeping artifacts, scoping retrieval, releasing the same way) are what make an answer checkable later.

What's not here, on purpose: the client, facility, equipment, code, exports and screenshots. The walkthrough uses newly written fictional inputs.
