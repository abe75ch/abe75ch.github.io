Tiltmeter: noticing a model drift before anything breaks

An open-source monitor that records the probabilities a model returns and alerts when they move. The code and its limits are public.

Problem
A model can change behaviour without any error: a new version, an edited question, or different inputs. Nothing visibly breaks until decisions go wrong.
My role
Author. Built on earlier MLOps work: pipelines, data-drift research and QA of ML systems.
Approach
Record probabilities per question, compare recent windows, and alert only on a real, significant change.
Outcome
In simulation, unchanged traffic raised an alert in at most 0.3% of checks, while a moderate real shift was caught every time.

How it works

It records the probabilities a model returns (TypeSafe's Jev) for every question, never the text, and raises four alerts:

  • version: the model behind the alias changed
  • drift: the spread of answers moved away from its baseline
  • edge: too many answers sit right next to the threshold the code acts on
  • accuracy: estimated accuracy fell, from the probabilities alone, with no labels

Decisions worth explaining

  • Effect size and p < 0.001 before alerting. A question needs at least 50 answers in each of two windows of up to 200, so small samples don't page anyone.
  • Never stores prompt text. Only probabilities, model name and a question fingerprint.
  • Two ways in. A Pydantic AI integration, or a local proxy for any client. The proxy never adds an API key and only accepts JSON, so other programs can't spend your quota through it.
  • Core uses the Python standard library only.

Limits, stated plainly

  • The accuracy estimate assumes the probabilities stay calibrated. It's an early warning, not a replacement for labelled checks.
  • Each window is compared with the one before it, so a very slow, steady slide can stay under the limits. A pinned reference window isn't built yet.
